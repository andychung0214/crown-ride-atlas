# CROWN RIDE ATLAS／狂輪誌設計規格

## 1. 專案定位

- 專案名稱：CROWN RIDE ATLAS
- 中文名稱：狂輪誌
- 類型：台灣公路車路線百科與騎乘圖鑑
- 核心主張：沿著山脈與海風，收藏島嶼上每一道值得騎乘的曲線。
- 平台：桌機瀏覽器優先，支援平板與行動觸控。
- 執行方式：直接開啟 `index.html`，或部署至任何靜態網站託管環境。
- 技術限制：HTML、CSS、Vanilla JavaScript；不使用前端框架、TypeScript、後端服務或建構工具。

## 2. 使用者與主要情境

### 2.1 目標使用者

1. 想搜尋台灣各地經典路線的公路車騎士。
2. 依距離、爬升與難度安排週末騎乘的進階騎士。
3. 想下載 GPX、查看地圖或收藏主題挑戰的使用者。
4. 想在本機補充私人路線、圖片與 GPX 的內容維護者。

### 2.2 核心任務

1. 依地區、難度、距離、爬升與關鍵字找到路線。
2. 在路線詳情頁了解路線故事、路況提醒、補給、地圖與海拔資訊。
3. 下載與地圖相同座標所產生的 GPX。
4. 探索一日雙塔、北高、武嶺與環島等主題挑戰。
5. 檢視環小台灣、大象等路線美學圖案。
6. 在瀏覽器本機新增、編輯、刪除、匯出與匯入路線資料。

## 3. 首版範圍

### 3.1 內容

- 60 條地區路線，涵蓋台灣 22 個縣市／區域。
- 8 條經典挑戰路線，包含一日雙塔、北高、太平山登高、西進武嶺與環島等主題。
- 6 組路線美學圖案，包含環小台灣與大象等輪廓。
- 每條路線至少包含：
  - 唯一識別碼、名稱、地區與類型。
  - 縮圖、短摘要與路線故事。
  - 距離、總爬升、難度、預估時間與標籤。
  - 騎乘提醒、補給建議與座標。
  - 地圖、SVG 海拔剖面與 GPX 下載。

路線數值與座標用於首版資訊展示與功能驗證。網站需明確提醒使用者：道路開放、施工、天候與補給狀態會變動，出發前應以主管機關與現場資訊為準。

### 3.2 不在首版範圍

- 會員、登入、多人同步與雲端資料庫。
- 即時路況、即時天氣、導航與騎乘追蹤。
- Strava、Garmin、ECPay 或其他第三方帳號整合。
- 伺服器端圖片處理、內容審核與版本歷程。
- 未經使用者操作的背景上傳。

## 4. 視覺方向

採用「A．峠之路誌」：日式編輯設計、地形圖語彙、紙張肌理與公路車資料標記的混合風格。

### 4.1 視覺原則

- 以溫暖米白紙色取代純白，搭配墨黑、灰綠與細緻分隔線。
- 標題具有刊物感，資料數字採清楚且穩定的等寬字體。
- 圖片比例一致，避免大量漂浮卡片、玻璃擬態與過度圓角。
- 路線卡以地區、名稱與三項關鍵數值形成固定閱讀節奏。
- 地圖、海拔剖面與座標標記使用同一主題強調色。
- 動畫只表達狀態變化，並尊重 `prefers-reduced-motion`。

### 4.2 四套主題

| 主題 | 角色 | 主色 | 輔助色 |
|---|---|---|---|
| 黃衫 | 總成績最佳 | `#F5D547` | 墨色 `#24271F` |
| 衝刺綠 | 衝刺積分 | `#19864A` | 淡綠灰 `#DDE5DC` |
| 登山圓點 | 登山王 | 紙白 `#F6F1E7` | 紅色 `#C83E36` |
| 白衫 | 年輕最佳 | `#F8F7F1` | 灰藍 `#59636D` |

所有主題均需維持 WCAG AA 文字對比，不能只用顏色傳達選取或難度。

### 4.3 已確認版面

- 首頁：編輯誌式主題路線開場、四主題切換、地區快速篩選與路線卡。
- 行動首頁：主圖與標題垂直排列、單欄路線卡、可橫向捲動的篩選器。
- 路線詳情：故事與數值開場，地圖為閱讀核心，旁欄呈現難度、提醒與 GPX。
- 編輯器：桌機為右側抽屜；行動裝置為全螢幕表單。

## 5. 資訊架構與導覽

採用 Hash Router，避免靜態託管需要伺服器重寫規則：

- `#/home`：首頁。
- `#/routes`：全部路線與篩選。
- `#/region/:regionId`：地區路線。
- `#/route/:routeId`：路線詳情。
- `#/challenges`：經典挑戰。
- `#/route-art`：路線美學。
- `#/editor`：本機資料管理。
- 無效網址導向可理解的找不到頁面，並提供返回路線索引的操作。

桌機主導覽包含「探索路線、經典挑戰、路線美學、騎乘誌」；行動版使用可鍵盤操作的導覽抽屜。搜尋與新增路線為全域操作。

## 6. 技術架構

### 6.1 執行模型

使用多支傳統 `<script defer>`，每支程式碼以 IIFE 建立在 `window.CrownRideAtlas` 命名空間下。純函式同時透過 CommonJS `module.exports` 暴露，讓 Node 內建測試執行器可直接測試。

不採用瀏覽器 ES Modules，原因是部分瀏覽器會限制 `file://` 下的跨檔案模組載入；此決策確保直接雙擊 `index.html` 仍可執行。

### 6.2 模組邊界

- `js/data/routes.js`：內建路線、挑戰與路線美學資料。
- `js/core/store.js`：內建資料與本機覆寫合併、備份、匯入與重設。
- `js/core/router.js`：Hash Router 解析與導覽。
- `js/core/theme.js`：主題切換、持久化與系統偏好。
- `js/core/filter.js`：搜尋、地區、難度與排序純函式。
- `js/core/gpx.js`：GPX 解析、驗證與輸出。
- `js/core/image.js`：圖片格式檢查、Canvas 縮放與壓縮。
- `js/ui/render.js`：安全 DOM 建立與頁面渲染。
- `js/ui/map.js`：Leaflet 地圖、SVG 降級與海拔圖。
- `js/ui/editor.js`：表單、圖片／GPX 上傳與刪除確認。
- `js/app.js`：應用程式啟動、事件協調與錯誤邊界。

各模組只透過明確函式介面交換資料。使用者輸入使用 `textContent` 或 DOM 屬性呈現，不使用未清理的 `innerHTML`。

### 6.3 路線資料模型

```text
Route {
  id, slug, name, regionId, regionName, category,
  summary, story, thumbnail, distanceKm, elevationGainM,
  difficulty, durationMinutes, tags[], cautions[],
  supplies[], coordinates[{ lat, lng, ele }], featured,
  challengeId?, artId?, createdAt, updatedAt
}
```

- `difficulty` 必須為 1–5 的整數。
- `coordinates` 至少需要兩個合法座標。
- 距離與爬升必須為有限非負數。
- 本機新增識別碼使用 `local-<timestamp>-<random>`，避免覆蓋內建資料。

## 7. 資料流與本機編輯

1. 啟動時讀取內建資料。
2. 從 `localStorage` 的 `crownRideAtlas.v1` 讀取新增、覆寫與刪除標記。
3. 驗證結構後合併為目前資料集合；無效紀錄忽略並顯示復原提示。
4. 篩選器只處理記憶體中的集合，不修改來源。
5. 編輯表單先驗證欄位、圖片與 GPX，再一次寫入本機儲存。
6. 匯出功能產生包含版本號與匯出時間的 JSON。
7. 匯入功能先預覽有效、衝突與略過筆數，確認後才覆寫。

圖片接受 JPEG、PNG 與 WebP，經 Canvas 轉為 WebP 或 JPEG，長邊不超過 1,600px，目標大小不超過 400KB。GPX 接受 `.gpx` 與標準 GPX XML，檔案上限 1MB。

若瀏覽器儲存空間不足，保留原資料、顯示原因，並提供先匯出備份或移除大型圖片的建議。

## 8. 地圖與 GPX

- 優先載入 Leaflet 與 OpenStreetMap 圖磚。
- Leaflet 不可用或圖磚載入失敗時，以原生 SVG 正規化座標後繪製路線。
- 海拔剖面使用路線座標中的 `ele` 值；缺少海拔時顯示「未提供海拔資料」。
- GPX 下載由目前路線座標即時產生，包含名稱、軌跡段與海拔。
- 上傳 GPX 後解析第一條有效軌跡，計算近似距離，並允許使用者確認是否更新表單數值。

## 9. 狀態、錯誤與安全

- 所有可恢復錯誤使用頁面內訊息或 `aria-live` 狀態區，不以原生警示框作為主要回饋。
- 刪除、重設與覆寫匯入必須二次確認。
- 無效圖片、GPX、JSON、路線網址與儲存空間不足均有明確錯誤訊息。
- Leaflet、圖磚或圖片失敗時保留文字、數值與替代圖，不讓頁面空白。
- 不讀取、不儲存、不輸出任何 `.env`、憑證、Token 或私人金鑰。
- 專案不含使用者提供的 Unsplash Access Key 與 Secret Key；相關金鑰應由擁有者撤銷並重新產生。

## 10. 無障礙與響應式

- 斷點：手機 `< 640px`、平板 `640–1023px`、桌機 `>= 1024px`。
- 所有互動可使用鍵盤操作，並具有可見焦點。
- 使用語意標題、導覽、按鈕、表單標籤與狀態區。
- 圖片具有描述性替代文字；裝飾地形紋理對輔助科技隱藏。
- 觸控目標至少 44×44px。
- 支援 200% 縮放、Reduced Motion 與高對比閱讀。
- 地圖不作為唯一資訊來源；距離、爬升、難度與提醒需以文字同步呈現。

## 11. 測試策略

### 11.1 自動測試

使用 Node 內建測試執行器 `node --test`，不安裝大型測試框架：

- 地區、關鍵字、難度與排序。
- 內建資料與本機新增／覆寫／刪除合併。
- 主題名稱、回退值與持久化。
- GPX 合法／無效 XML、座標解析與下載輸出。
- JSON 備份版本、匯入驗證與衝突處理。
- SVG 座標正規化與空資料處理。

### 11.2 瀏覽器驗證

- 以本機靜態伺服器驗證所有頁面與 Leaflet。
- 直接使用 `file://` 開啟 `index.html`，驗證核心導覽、篩選、主題與 SVG 地圖。
- 桌機 1440px、平板 768px、手機 390px 截圖檢查。
- 鍵盤導覽、焦點順序、對比、縮放與 Reduced Motion。
- 新增、編輯、圖片上傳、GPX 上傳、備份、匯入、刪除與重設。

## 13. 驗收條件

1. 直接開啟 `index.html` 可瀏覽核心內容，靜態伺服器下可使用 Leaflet 圖磚。
2. 四套主題可即時切換並在重新整理後保留。
3. 可依地區、關鍵字與難度篩選至少 60 條路線。
4. 每條路線詳情包含縮圖、數值、難度、地圖或 SVG 降級、提醒與 GPX 下載。
5. 經典挑戰與路線美學具有獨立索引與詳情入口。
6. 可在本機新增、編輯、刪除、備份、匯入及重設路線。
7. 自動測試全數通過，並留下桌機、平板與手機的瀏覽器驗證證據。
8. 儲存庫不包含憑證、Token、`.env` 或私人金鑰。
9. 完成程式碼審查與分支收尾後，先顯示遠端、分支與提交，再推送至指定 GitHub 儲存庫。
