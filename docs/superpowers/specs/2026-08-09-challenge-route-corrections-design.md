# 挑戰路線與路線美學修正設計

日期：2026-08-09
狀態：混合修正方案已取得使用者核准，待書面規格複核

## 背景

目前「北高」與「一日雙塔」是以數條短路線作為參考清單。挑戰卡片的第一個連結會開啟第一段短路線，因此名稱、地圖、GPX 與實際挑戰端點不一致。另一方面，路線美學資料雖然使用道路軌跡，部分實際幾何與「環小台灣」、「大象」等名稱差異過大，仍被公開列出，容易讓使用者誤以為是精準圖形。

使用者已核准混合修正方案：挑戰路線建立獨立的完整道路軌跡；路線美學加入可重現的幾何相似度閘門，只公開通過閘門的近似圖形。

官方地標名稱與位置參考：新北市官方使用「三貂角燈塔」名稱（[新北旅遊官方頁面](https://newtaipei.travel/zh-tw/Attractions/Detail/110112)），鵝鑾鼻燈塔參照國家公園與交通部觀光署資料（[墾丁國家公園官方頁面](https://www.taiwan.nps.gov.tw/home/zh-tw/attractions/20999.html)、[交通部觀光署燈塔資料](https://www.taiwan.net.tw/m1.aspx?sNo=0043550)）。

## 目標

- 「北高」卡片直接開啟一條由台北至高雄的 point-to-point 完整 GPX，地圖與 GPX 起點、終點、方向及統計一致。
- 「一日雙塔」卡片直接開啟一條由三貂角燈塔至鵝鑾鼻燈塔的 point-to-point 完整 GPX。
- 兩座燈塔若實際塔區含階梯、步道或不可騎路段，使用距離最近且可騎的公共道路作為 GPX 端點，並在介面明確標示「道路接點」與官方地標名稱，避免宣稱可騎入塔區。
- 保留既有分段路線，作為挑戰路線的補充參考，不再當作挑戰卡片的主連結。
- 路線美學採用固定的取樣、正規化與幾何距離計算；只有通過門檻、道路政策檢查與人工審核的圖形才進入公開路線美學清單。
- 所有修正維持靜態 HTML、CSS、Vanilla JavaScript、GitHub Pages、`file://` 開啟、GPX 下載與行動觸控相容性。

## 非目標

- 不在使用者瀏覽期間呼叫即時路線規劃服務。
- 不以圖形相似度凌駕合法道路、連續性、道路安全或路線資料品質。
- 不宣稱燈塔塔區本身可騎入，也不把圖形近似線宣稱為測量級或官方賽事路線。
- 不刪除既有短路線或使用者本機編輯資料。

## 採用方案

### 1. 新增兩條正式挑戰軌跡

新增正式路線識別碼：

- `challenge-north-south`：台北 → 高雄，`point-to-point`，西部主要可騎道路串接，途經城市與補給節點。
- `challenge-twin-towers`：三貂角燈塔 → 鵝鑾鼻燈塔，`point-to-point`，沿東北、東部及南迴／恆春可騎道路串接；北端與南端以道路接點標示。

兩條路線的開發種子由人工指定起點、終點及必要途經點，再以既有 BRouter `fastbike` 產生靜態軌跡。種子必須包含 `direction`、`profile`、`waypoints`、`referenceUrl`、`reviewStatus` 與審核說明。BRouter 回傳的 LineString 必須通過既有道路政策與軌跡驗證，才可寫入正式 bundle。

挑戰資料模型在既有路線欄位上增加：

```js
{
  id: "challenge-north-south",
  category: "經典挑戰",
  challenge: true,
  direction: "point-to-point",
  startLabel: "台北市道路接點",
  finishLabel: "高雄市道路接點",
  endpointNote: "地標名稱與道路接點分開標示，避免誤解為可騎入非道路區域。"
}
```

挑戰物件保留 `routeIds` 以相容既有多段挑戰；北高與雙塔改為以唯一正式挑戰路線作為第一主連結，並保留原有分段 `referenceRouteIds` 供延伸閱讀。挑戰卡片必須顯示「起點 → 終點」、完整路線距離與「開啟完整 GPX」；不可再以第一段參考路線作為主按鈕。

### 2. 路線美學相似度閘門

路線美學規格保留每個圖形的 `targetShape` 折線，但不再無條件將所有圖形加入 `routeArt`。新增純函式模組，執行以下固定流程：

1. 將實際道路軌跡取其水平邊界框，轉為 0–1 正規化座標。
2. 依累積道路距離將目標折線與實際軌跡各重採樣為 64 個點。
3. 以點對點平均距離、最大距離與方向反轉後的較小值計算 `shapeScore`；計算前不任意旋轉圖形，避免把不同方向的圖形誤判為相同。
4. 只有 `shapeScore <= 0.24`、`maxPointError <= 0.48`、軌跡通過道路政策且 `reviewStatus === "approved"` 時，才標記為 `near-match`。
5. `routeArt` 只由 `near-match` 項目建立。未通過者保留在開發稽核資料中，並在測試中確認不可出現在公開清單、首頁卡片或路線美學頁面。

圖形名稱需反映精確程度：通過項目若非官方精準圖形，名稱使用「近似」或「道路近似」；描述須說明這是沿公共道路繪製的近似線。若本批次沒有任何項目通過，頁面顯示「目前沒有通過幾何相似度檢查的公開圖形」，不可用錯誤命名填滿列表。

### 3. 地圖、GPX 與統計一致性

- Leaflet 地圖只繪製完整挑戰軌跡的真實座標，並自動縮放至完整範圍。
- 起點、終點標記取自正式軌跡第一點與最後一點；端點標籤同時顯示官方地標與可騎道路接點說明。
- GPX 下載使用相同完整軌跡；距離、爬升、下降、最高／最低海拔、坡度與主要爬坡資料全部以該軌跡計算結果為唯一來源。
- 軌跡載入失敗時不繪製推測線段，並停用下載按鈕。

## 程式碼與資料變更範圍

- `tools/route-data/seeds/`：新增兩條挑戰路線種子與端點參考來源。
- `scripts/` 與 `js/data/tracks/`：產生、註冊與驗證兩條完整挑戰 bundle；更新總量與分類檢查。
- `js/data/routes.js`：新增挑戰路線中繼資料、修正挑戰關聯、加入路線美學目標形狀與閘門結果。
- `js/core/` 或等效純函式檔案：新增正規化、重採樣及相似度計算，供瀏覽器與 Node 測試共用。
- `js/ui/render.js`：挑戰卡片改用完整挑戰路線主連結；路線美學頁只呈現通過閘門項目。
- `tests/`：新增端點與挑戰連結測試、幾何閘門測試，並更新正式路線數量與 bundle 完整性斷言。
- `docs/`：補充端點接點、圖形近似與人工審核限制。

## 測試與驗收條件

### 自動測試

- 北高資料的起點城市為台北、終點城市為高雄，方向為 `point-to-point`，主連結指向 `challenge-north-south`。
- 雙塔資料的起點文字包含「三貂角燈塔」、終點文字包含「鵝鑾鼻燈塔」，方向為 `point-to-point`，主連結指向 `challenge-twin-towers`。
- 兩條新軌跡皆通過相鄰點距離、海拔、坡度、距離單調性、道路政策與 `reviewStatus` 驗證。
- 公開 `routeArt` 每一項都具備 `near-match` 狀態且符合兩個幾何門檻；不合格圖形不會被渲染。
- 正式路線、軌跡 manifest 與 bundle 數量一致，既有 66 條地區路線與 6 條美學路線的相容性斷言改為明確區分「地區、挑戰、美學」分類。

### 手動與瀏覽器驗收

- 點選「北高」後，頁面標題、端點、地圖範圍、GPX 檔名與統計都呈現台北至高雄完整路線，而非台北短段。
- 點選「一日雙塔」後，頁面呈現三貂角燈塔至鵝鑾鼻燈塔完整路線，且端點道路接點說明可見。
- 路線美學頁不再列出幾何明顯不相符的錯誤命名；每個保留項目在地圖縮放後仍能辨識其近似圖形。
- 桌機、窄螢幕觸控與鍵盤操作均可開啟挑戰、查看地圖、下載 GPX；載入錯誤時不出現假線條。

## 風險與緩解

| 風險 | 緩解方式 |
| --- | --- |
| 長距離 BRouter 路線超時或超過服務限制 | 分批產生、固定節流與有限重試；結果靜態提交，瀏覽器不依賴服務。 |
| BRouter 選到高速公路、禁行或不適合公路車路段 | 延續既有道路政策硬閘門；失敗即停止發佈並調整途經點。 |
| 燈塔塔區不是可騎道路 | 使用最近公共道路接點，介面同時顯示官方地標與接點說明。 |
| 圖形閘門過嚴導致沒有公開美學路線 | 以測試固定門檻與稽核報告呈現空集合，不為了填滿頁面降低道路安全條件。 |
| 新分類破壞舊版挑戰或本機資料 | 保留既有 `routeIds` 與 `localStorage` 識別碼，新增欄位採向後相容。 |

## 書面規格自我檢查

- 需求：端點正確、道路可騎、海拔坡度沿用完整軌跡、錯誤圖形不公開，均已明確定義。
- 範圍：資料種子、產生器、靜態 bundle、介面、測試與文件均列出；未擴張至後端或即時導航。
- 可驗證性：挑戰端點、主連結、相似度門檻、道路政策、數量與瀏覽器操作都有自動或手動驗收條件。
- 安全性：不新增 API 金鑰、token、`.env` 或私人憑證；官方來源僅保存公開網址。
- 相容性：保留舊有分段路線、GPX、localStorage、GitHub Pages 與 `file://` 執行方式。
