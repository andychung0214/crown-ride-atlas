# 真實公路車路線與海拔坡度改造設計

日期：2026-07-26  
狀態：已完成對話設計核准，待書面規格複核

## 背景

目前 66 條地區路線由地區中心點搭配公式產生，每條只有 8 個示意座標；座標沒有貼合道路，會穿越建築、山區及不可騎區域。海拔也由公式估算，無法反映真實高度與坡度。另有 6 條路線美學以幾何形狀直接轉成座標，並未沿道路繪製。兩者合計為網站目前的 72 條路線。

地圖元件只是依序連接既有座標，因此問題根源是路線資料，不是 Leaflet 或 OpenStreetMap 圖磚樣式。

## 目標

- 將 66 條地區路線與 6 條路線美學，共 72 條可開啟的路線軌跡，全部替換為沿真實道路的公路車路線。
- 以合法、可通行且適合公路車為最高優先；現有距離、爬升與時間可由真實軌跡重新計算並覆蓋。
- 提供以實際里程為基準的詳細海拔與坡度資料。
- 保持純 HTML、CSS、Vanilla JavaScript、GitHub Pages 與直接開啟 `index.html` 的相容性。
- 保留 GPX 下載、GPX 上傳、本機編輯與 `localStorage` 功能。

## 非目標

- 不提供即時轉向導航或騎乘中的語音導航。
- 不在網站瀏覽期間呼叫路線規劃 API。
- 不把 SRTM 地形高度宣稱為測量級或即時道路高度。
- 不保證道路永遠開放；施工、災害、活動管制與現場標誌仍以當下狀況為準。
- 不建立後端服務、使用者帳號或雲端同步。

## 採用方案

採用「人工策劃地標＋BRouter 公路車導航＋靜態保存軌跡」。

每條路線先由人工定義起點、途經地標、山口、折返點或終點，再以 BRouter `fastbike` 公路車設定產生沿 OpenStreetMap 路網的軌跡。BRouter 回傳的道路座標與 SRTM 海拔只在開發階段取得；整理後的靜態資料提交至版本庫，網站執行時不依賴 BRouter、不需要 API 金鑰。

選用理由：

- BRouter 專注自行車路線、支援自行車道路權限、經由點、替代路線及海拔。
- 開發階段可取得包含數百個道路點與海拔的 GeoJSON。
- 靜態保存可避免公開服務限流、服務中斷、CORS、使用者隱私及離線失敗。
- 人工途經地標可避免導航引擎產生雖合法但不符合路線名稱或騎乘目的的捷徑。

未採用方案：

- 外部 GPX 蒐集：72 條路線的授權、品質、方向與更新頻率難以一致。
- 瀏覽器即時路線規劃：會使核心功能依賴第三方服務與網路狀態。

## 資料架構

### 人工路線種子

新增開發用種子資料，每條路線包含：

```js
{
  id: "new-taipei-yangjin-3p",
  direction: "loop",
  profile: "fastbike",
  waypoints: [
    { name: "起點名稱", lat: 25.000000, lng: 121.000000, role: "start" },
    { name: "途經地標", lat: 25.000000, lng: 121.000000, role: "via" },
    { name: "終點名稱", lat: 25.000000, lng: 121.000000, role: "finish" }
  ],
  reviewStatus: "pending"
}
```

`direction` 只接受：

- `loop`：環線，終點回到起點。
- `out-and-back`：原路或近似原路折返。
- `point-to-point`：甲地至乙地。

路線美學使用相同結構，但允許更多 `via` 點以沿真實街道近似圖形。圖形辨識度不得優先於自行車合法性與道路連續性。

### 產生工具

新增本機 Node.js 工具，依序執行：

1. 驗證種子識別碼、方向、地標名稱與座標。
2. 以固定節流間隔呼叫 BRouter。
3. 對暫時性網路錯誤使用有限次數重試。
4. 驗證回傳為連續 LineString、座標位於合理區域且每點含海拔。
5. 一般路段保留約每 30–80 公尺一點，最大相鄰距離 80 公尺；髮夾彎以 RDP 幾何候選加密，可保留 30 公尺以下必要片段。每條重採樣軌跡相對原始 BRouter 折線的距離誤差須 ≤ 0.5%，原始點到重採樣折線最大偏差須 ≤ 5 公尺。
6. 計算累積距離、平滑海拔、總爬升、總下降、最低及最高海拔。
7. 使用 100 公尺移動距離視窗計算坡度，避免單點高度雜訊。
8. 偵測主要爬坡分段。
9. 先寫入暫存結果並執行完整驗證；只有全批路線通過才更新正式資料，禁止部分覆寫。

產生工具不含 API 金鑰、token、`.env` 或私人憑證。工具輸出的來源資訊包含 BRouter profile、資料產生時間及人工審核狀態。

### 發佈資料

路線卡片所需的輕量中繼資料繼續由主要路線資料提供，包含：

- 名稱、地區、分類、摘要與標籤。
- 重新計算後的距離、爬升、難度及預估時間。
- 對應軌跡 bundle 的識別碼。
- 軌跡來源、產生日期與人工審核狀態。

完整軌跡依地區拆成約 23 個傳統 JavaScript bundle。每個 bundle 以 IIFE 註冊該地區的 3 條一般路線；路線美學使用獨立 bundle。傳統 `<script>` 延遲載入可同時支援 HTTP(S) 與 `file://`，不使用會被本機檔案 CORS 阻擋的 `fetch()`。

軌跡載入器提供：

```js
loadTrack(route) => Promise<Track>
getCachedTrack(routeId) => Track | null
```

`Track` 結構：

```js
{
  routeId: "new-taipei-yangjin-3p",
  source: {
    router: "BRouter",
    profile: "fastbike",
    elevation: "SRTM",
    generatedAt: "ISO-8601",
    reviewedAt: "ISO-8601",
    reviewStatus: "approved"
  },
  coordinates: [
    {
      lat: 25.000000,
      lng: 121.000000,
      ele: 120,
      distanceKm: 0,
      gradePct: 0
    }
  ],
  summary: {
    distanceKm: 87.4,
    elevationGainM: 2146,
    elevationLossM: 2146,
    minimumElevationM: 12,
    maximumElevationM: 1030,
    maximumSustainedGradePct: 12.4
  },
  climbs: [
    {
      startDistanceKm: 12.3,
      endDistanceKm: 18.7,
      distanceKm: 6.4,
      gainM: 482,
      averageGradePct: 7.5,
      maximumGradePct: 11.8
    }
  ]
}
```

## 距離、海拔與坡度計算

- 累積距離使用相鄰有效座標的 Haversine 距離。
- 海拔剖面保留原始 SRTM 高度作為資料來源；顯示與坡度計算使用距離加權平滑結果。
- 坡度以 100 公尺移動距離視窗計算：

```text
坡度百分比 = 視窗高度差 ÷ 視窗水平距離 × 100
```

- 總爬升只累加經平滑後的有效上升，避免 SRTM 微小抖動被重複累加。
- 最大坡度使用持續距離視窗，不顯示單一座標造成的瞬間極值。
- 主要爬坡分段至少持續 500 公尺且累積上升至少 30 公尺。
- 距離、爬升、最高海拔、時間與爬坡資料以新軌跡計算結果為唯一來源，不保留舊有估算值。

## 地圖設計

- Leaflet 使用完整真實座標畫線並自動縮放至軌跡範圍。
- 顯示明確的起點、終點與行進方向箭頭。
- 顯示人工途經地標，地標名稱來自路線種子。
- 地圖線條延續目前四主題色，外框維持足夠對比。
- Leaflet 或圖磚不可用時，SVG 離線輪廓使用相同真實座標，不得退回公式假路線。
- 軌跡資料尚未載入時顯示載入狀態。
- 軌跡 bundle 失敗時顯示「路線資料暫時無法載入」，地圖與 GPX 下載停用；不得畫出推測線段。

## 海拔與坡度介面

- X 軸使用實際累積里程，Y 軸使用海拔公尺。
- 坡度分色：
  - 下坡：藍色。
  - 0–3%：灰綠。
  - 3–6%：綠色。
  - 6–9%：黃色。
  - 9–12%：橘色。
  - 12% 以上：紅色。
- 滑鼠移動、鍵盤焦點或行動觸控時顯示目前里程、海拔及平滑坡度。
- 圖表提供可理解的軸標籤、單位、坡度圖例及無障礙文字摘要。
- 統計區新增最低海拔、最高海拔、總下降與最大持續坡度。
- 主要爬坡列表顯示起訖里程、長度、爬升、平均坡度與最大坡度。
- 標示「海拔取自 SRTM 地形模型，適合路線規劃，並非測量級資料」。

## GPX 與編輯相容性

- 下載 GPX 時使用已載入的完整真實軌跡與海拔。
- 軌跡尚未載入或載入失敗時停用下載，並顯示原因。
- 上傳 GPX 的既有流程保留；匯入後使用相同距離、海拔與坡度分析函式。
- 使用者編輯中繼資料時不得破壞內建軌跡參照。
- 使用者上傳的新 GPX 繼續儲存在 `localStorage`；內建地區 bundle 不寫入 `localStorage`。
- 舊版 `localStorage` 覆寫資料需進行相容轉換；無法轉換時保留備份並提示使用者重新匯入，不可靜默遺失。

## 品質閘門

每一條路線都必須通過以下自動檢查：

- 識別碼唯一且可對應既有路線中繼資料。
- 至少包含 2 個人工地標及合理數量的道路座標。
- 相鄰座標距離不得異常跨越；允許的最大間距由取樣規則決定並在測試中固定。
- 每個座標的緯度、經度、海拔、累積距離及坡度皆為有限值。
- 累積距離單調遞增。
- 軌跡重算距離與 summary 的差異在固定容許範圍內。
- 總爬升、總下降及海拔範圍合理且不為公式預設值。
- 起點、途經地標與終點位於軌跡容許距離內。
- BRouter profile 固定為核准的公路車設定，並保留來源紀錄。
- `reviewStatus` 必須為 `approved` 且有 `reviewedAt`，否則 GitHub Pages 部署測試失敗。

人工檢查涵蓋全部 72 條路線：

- 在 OpenStreetMap／Leaflet 上檢查軌跡是否貼合道路。
- 檢查是否經過路線名稱對應的地標、山口或道路。
- 檢查高速公路、禁止自行車路段、樓梯、私人道路及明顯不適合公路車的未鋪裝路徑。
- 檢查環線方向、折返方向與起終點合理性。
- 路線美學須同時檢查道路合法性與縮放後的圖形辨識度。
- 記錄審核日期；網站顯示資料日期與道路狀況提醒。

## 測試策略

### 單元測試

- 距離與累積里程。
- 100 公尺坡度視窗。
- 海拔平滑與總爬升去雜訊。
- 主要爬坡分段偵測。
- 坡度分色邊界。
- 軌跡資料契約與 bundle 註冊。
- 延遲載入、快取、重複呼叫與載入失敗。
- GPX 匯入後分析與真實軌跡 GPX 輸出。
- 舊版 `localStorage` 相容轉換。

所有行為變更先建立會因現況缺陷而失敗的測試，再實作最小修改使其通過。

### 資料測試

- 72 條軌跡完整性。
- 全部人工審核狀態。
- 距離、海拔與坡度有限值。
- 地標與軌跡接近度。
- 無殘留 `buildCoordinates()` 或幾何形狀直線轉座標的正式資料。

### 瀏覽器測試

- 桌機與手機檢查首頁初始載入量。
- 逐一開啟 72 條路線詳情並確認地圖、海拔圖、坡度提示與 GPX 狀態。
- 驗證滑鼠、鍵盤及觸控圖表提示。
- 驗證四主題的路線、坡度分色、圖例與文字對比。
- 模擬 bundle 404 與 Leaflet 圖磚失敗。
- 驗證 GitHub Pages 專案子路徑及 `file://` 直接開啟。

### 上線驗證

- `npm test` 全數通過。
- JavaScript 語法檢查與 `git diff --check` 通過。
- GitHub Actions Pages workflow 結論為 `success`。
- 公開首頁、CSS、JavaScript、地區軌跡 bundle 與 GPX 路徑回應正常。
- 公開網站抽查首頁、代表性平路、海岸、山岳、離島與路線美學；主控台無錯誤。

## 風險與緩解

- 公開 BRouter 服務限流：產生工具採節流、有限重試與分批快取；網站執行時不呼叫服務。
- OSM 道路標記錯誤或過期：全部路線人工審核，並顯示道路可能變動的提醒。
- SRTM 樹冠、橋梁與隧道高度誤差：使用 100 公尺平滑、持續坡度及資料限制說明。
- 軌跡資料過大：依地區拆分並延遲載入，不在首頁一次下載全部座標。
- `file://` 動態資料限制：使用傳統 script bundle 註冊，不使用 `fetch()` 載入軌跡。
- 72 條路線改造工作量高：按地區分批產生與審核，但部署閘門要求全部核准後才能對外宣稱完成。
- 現有本機覆寫資料相容性：加入明確轉換、備份及錯誤提示，禁止靜默清除。

## 驗收條件

只有同時符合以下條件才可宣稱完成：

1. 66 條地區路線及 6 條路線美學均不再使用公式或幾何假座標。
2. 72 條路線全部由 BRouter 公路車路網產生並完成人工道路檢查。
3. 距離、海拔、爬升、坡度與爬坡分段全部由真實軌跡重算。
4. 地圖、SVG fallback、GPX 與海拔圖使用同一份軌跡資料。
5. 海拔圖具實際里程軸、坡度分色、滑鼠／鍵盤／觸控提示與詳細統計。
6. 軌跡依地區延遲載入，GitHub Pages 與 `file://` 均可使用。
7. 自動測試、72 條人工審核、桌機與手機瀏覽器驗證及 GitHub Pages 上線驗證全部通過。
8. README、測試計畫、驗證紀錄、資料來源與授權說明均已更新。
