# bike100 功能對照與路線美學誠實化規格

## 背景

目前「環小台灣」公開路線實際是台中市區約 26.9 公里的短迴圈，雖然道路稽核與幾何閘門通過，畫面仍不像台灣輪廓，容易讓使用者誤以為是環台路線。參考 `bike100.tw` 的公開索引可見，騎乘者需要以區域、縣市、最陡坡度、行程時間、關鍵字與排序快速找到路線，並能標記「騎過此路線」。

## 已核准方向（方案 A）

1. 不再以目前的市區小迴圈冒充「環小台灣」；本次先從公開路線美學清單移除它。
2. 保留已通過道路政策與軌跡驗證的正式道路資料，不直接複製 bike100 會員限定詳情、圖片或受限 GPX。
3. 補齊公開索引層的功能對照：熱門／最新／難度／距離／爬升排序、坡度／區域／縣市／行程時間篩選、結果分頁與「騎過此路線」本機標記。
4. 路線詳情保留 Leaflet／SVG 地圖、GPX 下載、海拔與坡度分析，並顯示資料來源與道路近似限制。
5. 未來只有取得可追溯、可驗證且確實呈現台灣輪廓的完整環台道路 GPX，才可重新命名為「環小台灣」。

## 使用者故事

- 作為探索路線的騎士，我可以依地區、縣市、坡度與行程時間縮小結果，快速找到適合今天的路線。
- 作為已完成路線的騎士，我可以在本機標記「騎過」，下次仍能看見完成狀態。
- 作為重視資料可信度的騎士，我不會看到與道路實際形狀不相符的路線美學名稱。
- 作為規劃長途行程的騎士，我可以在詳情頁看到距離、爬升、最高點、最大坡度、坡度分布與資料來源。

## 範圍

### 本次包含

- 路線資料新增可供篩選與排序的標準化欄位：`maxGradePct`、`areaId`、`durationBand`、`completed`（完成狀態由本機儲存層提供）。
- `js/core/filter.js` 支援關鍵字、區域、縣市、難度、最陡坡度區間、行程時間區間與排序。
- 路線總覽新增篩選結果數、每頁 24 筆分頁、上一頁／下一頁與可鍵盤操作的頁碼。
- 路線卡新增完成切換按鈕，狀態儲存在 `localStorage`，不需要帳號或後端。
- 路線美學公開清單移除 `route-art-little-taiwan`；路線詳情仍保留明確的道路近似資料契約，避免殘留死連結。
- 測試涵蓋篩選、排序、分頁、完成狀態、路線美學公開清單與空狀態。
- README、PLAN、TEST-PLAN、VERIFICATION 補上參考網站對照與受限資料不複製的說明。

### 本次不包含

- 不抓取、重製或批次匯入 bike100 的 227 筆會員路線、圖片、GPX、會員資料或登入狀態。
- 不建立會員系統、雲端同步、即時定位、即時路況或後端服務。
- 不以人工畫布折線替代真實道路，也不降低道路政策與軌跡驗證門檻來填滿路線美學。
- 不在沒有經過道路與幾何稽核的情況下重新加入「環小台灣」。

## 設計與資料規則

- 「區域」沿用北／中／南／東台灣；「縣市」沿用現有 22 個地區識別碼。
- 坡度篩選沿用 bike100 可理解的區間：5–9%、10–14%、15–19%、20–25%。
- 行程時間以分鐘計算後映射至 `under-1h`、`1-2h`、`2-3h`、`3-4h`、`4-5h`、`5-8h`、`8-12h`、`12h-plus`。
- 缺少可靠 `maxGradePct` 或 `durationMinutes` 的自訂路線不得被錯誤歸入篩選區間，介面需顯示「未提供」。
- 排序必須穩定：熱門、最新、難度、距離、爬升與名稱；相同值以 `featured` 或名稱作次要排序。
- 完成狀態只儲存路線識別碼集合，不儲存帳號、地理位置或任何憑證。

## 驗收條件

1. 路線美學頁不再公開「環小台灣」或任何不相符的假輪廓；沒有可公開項目時顯示誠實空狀態與未來重新納入條件。
2. 路線總覽可同時使用關鍵字、區域／縣市、難度、坡度與時間篩選，結果數與分頁正確。
3. 變更排序或篩選後頁碼重設為第一頁；重新整理頁面不會遺失主題與完成標記。
4. 在桌機與行動寬度下，篩選列、路線卡、分頁與完成按鈕可操作且無水平溢位。
5. `npm test`、`npm run tracks:validate`、`npm run verify` 全部通過，並以瀏覽器檢查首頁、路線索引、路線美學空狀態與代表性路線詳情。
6. 推送前顯示 origin remote、`main` 分支與完整 commit SHA；GitHub Pages 工作流程成功後提供公開網址。
