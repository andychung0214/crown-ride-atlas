# 公路車零件百科與 GPS Art 下載擴充設計規格

日期：2026-08-21  
狀態：設計內容已由使用者逐節核准，文件待最終複核

## 1. 背景與目標

CROWN RIDE ATLAS 已有 68 條正式路線、23 個公開軌跡資料包與 22 件台灣 GPS Art 作品；其中只有 2 件 GPS Art 具有站內核准軌跡，其餘作品主要提供來源查核資料。

本次擴充有兩個目標：

1. 在適合的位置建立可互動的「公路車百科」，以森林綠公路車側視圖、導引線與詳細文字，說明公路車主要零件。
2. 補強「路線美學」的軌跡取得能力，逐條查核公開 GPX／KML／KMZ／GeoJSON，在尊重來源授權的前提下提供一鍵下載。

本功能不得讓第三方 GPS Art 資料混入正式路線索引，也不得改變既有正式路線、挑戰、地圖、本機編輯、完成標記或 GPX 下載契約。

## 2. 核准方案與設計原則

採用方案 A：資料驅動互動百科，加上 GPS Art 三狀態來源模型。

共同原則：

- 不使用人工手繪軌跡冒充原作，不從作品圖片反推座標。
- 不讀取登入 Cookie、權杖、私人活動或使用者瀏覽器中的憑證。
- 不把權利不明的第三方 GPX 複製進版本庫。
- 資料缺少、來源失效或下載需登入時，介面必須誠實標示，不能偽裝成可公開下載。
- 新增模組使用專屬資料、程式與 CSS 類別，避免影響現有功能。
- 所有重要互動均支援滑鼠、鍵盤與行動觸控，且不以顏色作為唯一提示。

## 3. 資訊架構

### 3.1 公路車百科

- 導覽列新增「公路車百科」，hash 路由為 `#/bike-parts`。
- 首頁新增「認識你的公路車」入口卡片。
- 百科頁是獨立資訊頁，不加入一般路線、挑戰或路線美學的篩選資料。
- 首版不建立每個零件的獨立路由；頁內選取狀態足以完成閱讀與操作。

### 3.2 路線美學

- 沿用 `#/route-art`。
- 保留既有 22 件作品及既有來源紀錄。
- 以 19 件 ShapeMiles 台北 GPS Art 作為新增候選；每件都必須通過下載與座標驗證後才能上架。
- Mobile01／YouTube 已找到的 Strava、Garmin 原始路線可補入 `routeSourceUrl`，但需要登入或沒有匿名下載時不得標示為公開 GPX。
- 正式 `Data.routes` 必須維持 68 條，正式 `TrackManifest` 必須維持 23 個資料包。

## 4. 公路車百科內容模型

建立 `js/data/bike-parts.js`，輸出凍結的零件分類與零件資料。每個零件至少包含：

```js
{
  id: "top-tube",
  name: "上管",
  categoryId: "frame-fork",
  number: 1,
  hotspot: { x: 42, y: 27 },
  labelAnchor: { x: 24, y: 13 },
  purpose: "…",
  materials: "…",
  adjustment: "…",
  maintenance: "…",
  warningSigns: "…",
  relatedParts: ["head-tube", "seat-tube"],
  workshopAdvice: "…"
}
```

`hotspot` 與 `labelAnchor` 使用 SVG `viewBox` 座標或正規化百分比，讓桌機與手機共用同一份幾何資料。任何文字欄位不得以 HTML 字串插入頁面。

## 5. 公路車百科呈現與互動

### 5.1 視覺

- 使用專案內以程式碼建立的公路車側視 SVG，不依賴第三方圖片或生成式點陣圖。
- 車架主色為森林綠，背景沿用米白紙張與細緻等高線／印刷紋理。
- 導引線與標籤以墨色為主，四種領騎衫主題只用於選取、分類與焦點提示。
- 車體比例、零件連接及導引位置以可辨識性優先，不加入無功能裝飾。

### 5.2 桌機

- SVG 左右分區配置零件標籤與導引線。
- 滑鼠指向同步突顯零件、標籤與導引線。
- 點擊或按下 Enter／Space 選取零件；選取狀態不依賴懸停。
- 右側詳細面板顯示七類說明，並提供前一個／下一個零件操作。

### 5.3 手機與觸控

- 圖上使用編號熱點，主要文字改在下方依分類排列，避免標籤互相遮擋。
- 支援雙指縮放與拖曳，同時提供放大、縮小與重設按鈕。
- 點擊清單或熱點會選取同一零件並展開詳細說明。
- 操作控制至少 44 × 44px；長文字、放大字級與 320px 寬度不得造成水平溢位。

### 5.4 無障礙與降級

- SVG 有可存取名稱與說明；每個互動熱點有可辨識名稱、鍵盤順序與清楚焦點樣式。
- 選取狀態同時使用線條、圖形與文字，不只改變顏色。
- 使用者設定 `prefers-reduced-motion` 時停用非必要轉場。
- SVG 或互動初始化失敗時，完整文字零件清單仍可閱讀。

## 6. GPS Art 三狀態契約

### 6.1 `track-ready`

- 具有可在本站合法保存的已核准分段座標。
- 顯示真實站內地圖、來源資訊與「下載 GPX」。
- 地圖與 GPX 必須共用同一份 `segments`，不得跨段補線。

### 6.2 `source-download`

- 原始平台提供不需使用本站憑證的公開下載端點，但來源條款不允許或未明確允許本站重新發布完整軌跡。
- 本站保存來源網址、格式、查核日期、檔案 SHA-256、點數與座標邊界等驗證摘要，不保存完整座標。
- 顯示「從來源下載 GPX」，明確標示下載由原平台提供。
- 不顯示本站軌跡地圖，避免以暫存或鏡像方式重新發布第三方幾何。

### 6.3 `source-only`

- 有足以證明作品的公開來源，但無可匿名、合法且穩定取得的軌跡。
- 只顯示作品與來源資料，標示「公開軌跡待取得」。
- 可提供「查看原始作品」或「查看原始路線」；需要登入的路線必須明示。

### 7.2 Mobile01、YouTube、Strava 與 Garmin

- 將已由原作者文章或影片說明證實的 Strava／Garmin 路線補為 `routeSourceUrl`。
- Strava、Garmin 頁面若需要登入，僅提供「查看原始路線」，不將其宣稱為匿名 GPX。
- 不呼叫需要 OAuth 權杖的 Strava 匯出 API，也不利用使用者已登入的瀏覽器狀態取得檔案。
- 活動頁有道路逆向、私人社區、田地或狹窄通道等警告時，必須保留原始活動類型與安全說明，不宣稱適合公路車。

### 7.3 其他直接檔案

- 先前查核失敗的臥虎 GPX 可重新嘗試公開下載。
- 只有來源明確允許本站保存與重新提供時才可升級為 `track-ready`；否則最多為 `source-download`。
- TLS、HTTP、解析或座標驗證失敗時維持 `source-only`，並記錄失敗原因。

## 8. 下載來源驗證與資料流

建立獨立來源驗證腳本，接受 GPX、KML、KMZ 與 GeoJSON。流程如下：

1. 只接受 HTTPS 來源與預先列入候選清單的主機。
2. 限制重新導向次數、下載大小與逾時，避免無限等待或異常資源消耗。
3. 以內容而非副檔名判定格式，拒絕 HTML 登入頁、錯誤頁與空檔。
4. 解析每個 segment，驗證經緯度為有限數值、點數合理且位於台灣合理邊界。
5. 檢查同段相鄰點是否出現不合理跳點；多段資料不得為了視覺連續而補線。
6. 計算來源檔 SHA-256、總點數、分段數與座標邊界。
7. `source-download` 只把驗證摘要寫入資料檔，完整檔案留在暫存記憶體並於處理後丟棄。
8. 只有授權可保存的來源才轉換為正規化站內 GPX／segments，並經人工核准後更新產物。

一般 `npm test` 不呼叫外部網路。來源現場查核使用獨立指令，避免外站短暫中斷使一般測試或 GitHub Pages 部署失敗。

## 9. 路線美學頁面調整

- 篩選改為：全部、自行車、跑步／步行、可下載 GPX、站內地圖。
- 頁首統計分開顯示作品總數、站內地圖數、來源端可下載數與待取得數。
- 所有卡片顯示作品名稱、圖形、活動類型、地區、來源平台、作者（來源有提供時）、查核日期及軌跡狀態。
- `track-ready` 顯示 Leaflet／SVG 降級地圖、站內 GPX 與原始來源。
- `source-download` 顯示來源下載按鈕與外部平台提示，不顯示假地圖。
- `source-only` 顯示文字型圖形標記、來源按鈕與「公開軌跡待取得」。
- 外部連結使用 `target="_blank"`、`rel="noopener noreferrer"`；不得把跨來源 `download` 屬性當作成功保證。
- 篩選結果以 `aria-live` 播報；空結果提供清除篩選操作。

若 19 件 ShapeMiles 候選全部通過，圖鑑目標數量為 41 件：2 件 `track-ready`、19 件 `source-download`、20 件既有 `source-only`。實際發布數量必須以驗證結果為準，不得用虛構資料補足。

## 10. 錯誤處理與安全

- 單筆百科資料不完整：測試與開發驗證應 hard-fail；瀏覽器正式頁面仍顯示其餘合法零件與文字降級內容。
- SVG 初始化失敗：保留可閱讀的分類清單與詳細文字。
- 外部 GPX 失效：不在瀏覽器背景偷偷改抓其他來源；保留作品卡並顯示最近查核日期。
- 外部連結只能來自允許的 HTTPS 網址；渲染使用安全 DOM API，不插入來源 HTML。
- 解析器拒絕過大檔案、巢狀壓縮異常、非有限座標及台灣範圍外資料。
- 專案、文件、測試產物與 Git 歷史不得包含 Cookie、權杖、API 金鑰、`.env` 或私人金鑰。

## 11. 測試與驗收

### 11.1 自動測試

1. 百科精確包含 32 個唯一零件 ID，分類、編號、座標與七類說明完整。
2. 每個 `relatedParts` 都指向存在的零件，SVG 熱點與資料 ID 一一對應。
3. 路由、導覽列、首頁入口、百科標題與文字降級內容正確。
4. 零件可透過點擊、Enter、Space、清單與熱點選取；縮放有上下限且重設可恢復。
5. `track-ready`、`source-download`、`source-only` 欄位契約互斥且完整。
6. 來源下載網址必須為允許的 HTTPS 主機；外部連結具有安全屬性。
7. 五種 GPS Art 篩選、數量統計、空狀態與按鈕條件正確。
8. GPX、KML、KMZ、GeoJSON 解析涵蓋有效檔、HTML 偽裝、超大檔、壓縮異常、缺座標、跨出台灣及異常跳點。
9. `source-download` 不得含完整 `segments`；`track-ready` 的地圖與 GPX 必須共用核准 segments。
10. `Data.routes.length` 維持 68，正式 validator 維持 23 個資料包／68 條路線。
11. `npm run verify`、`git diff --check` 與安全掃描全部通過。

### 11.2 瀏覽器驗證

在本機 HTTP 及發布候選版驗證：

- 桌機可見森林綠公路車、完整導引線與詳細面板。
- 鍵盤可依焦點順序選取零件，焦點與選取狀態清楚。
- 390px 與至少一個平板尺寸可使用熱點、分類清單、放大、縮小、拖曳與重設，無水平溢位。
- 四種網站主題下文字、導引線、焦點及狀態標籤皆有足夠辨識度。
- 至少一件站內 GPX、一件來源端 GPX 及一件 source-only 的按鈕與狀態正確。
- 19 件候選的公開下載端點逐件驗證；任何失敗都必須記錄，不得宣稱成功。
- 原有首頁、一般路線、北高／雙塔、路線詳情、地圖與本機編輯器沒有阻斷錯誤。

## 13. 明確不在本次範圍

- 後端服務、會員帳號、遠端投稿、留言、評分與資料庫。
- 繞過 Strava、Garmin 或其他平台登入與存取限制。
- 鏡像、重新發布或修改授權不明的第三方 GPX。
- 由圖片或形狀名稱人工描繪原作軌跡。
- 將跑步／步行 GPS Art 宣稱為適合公路車的道路路線。
- 改寫既有 68 條正式路線或 23 個軌跡資料包。
